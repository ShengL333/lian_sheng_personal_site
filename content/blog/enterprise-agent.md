Agent 很火，各种 Demo 层出不穷：能写报告的、能排行程的、能当客服的。但一个残酷的事实是——真正跑进企业日常流程、持续被使用的 Agent，屈指可数。

问题不一定出在模型能力。大模型越来越聪明，幻觉在降、工具调用在稳。真正难的是**从 Demo 到业务系统的鸿沟**：Demo 只要证明"AI 会思考"，业务系统要的是"AI 在真实约束下可靠地完成任务"。我做过排程、数字人、对话产品，也带过团队评估 Agent 能力边界，以下是我看到的 8 道坎。

## 坎一：企业流程比想象中复杂

企业流程不是一个 Prompt 能描述清楚的。一次排程背后是设备、物料、人员、订单优先级、交期承诺的一堆规则；一份工单流转涉及多个部门、多种例外。大量隐性规则根本没有文档，只存在于业务人员的经验里——"这个客户要特殊处理""这批料这批设备不能用""周五下午不要排巡检"。

需求调研最难的，不是问出流程，而是把业务人员的**经验**翻译成可执行的规则。这一步做不好，后面 Agent 表现再聪明，也建在错误的流程认知上。

## 坎二：概率性 vs 确定性，是天然冲突

大模型天然是概率的：同一个问题，它今天这么答，明天可能换个说法，极端情况下还会抽风。对话产品能容忍这点——答错了是体验问题，重说一遍就行。

但业务系统不能。订单、设备、资金、客户，每一步执行都要可预测、可审计、可追责。企业真正关心的不是"你能不能做"，而是"**错了怎么办**"。一个 Agent 能在 95% 的场景下排得漂亮，但剩下 5% 怎么兜底、怎么让人发现、怎么回滚，决定了它能不能上线。AI 工程里那些"无聊"的词——可观测、eval、降级、HITL——恰恰是它能不能进业务的关键。

## 坎三：不是所有业务都适合 Agent

这是最常见的失败根源：**先有 Agent，再找场景**。Agent 应该是最差的选择，而不是第一选择：

- 固定规则流程 → 用 Workflow，确定性、可审计、零幻觉风险
- 精确查询 → 用数据库 / 搜索引擎，别让模型记数字
- 企业知识问答 → 用 RAG
- 只有**复杂、动态、需要判断和多步工具调用**的任务，才真正需要 Agent

很多项目失败，是因为团队把 Agent 当成了"更聪明的全自动方案"去套一个本不需要它的场景。场景选错了，Agent 再强也是杀鸡用牛刀，还得给牛刀擦血。

## 坎四：企业数据并没有为 AI 准备好

Agent 的能力上限，往往取决于企业的数据治理水平——而不是模型。而企业数据通常是这样：

- 散落在 ERP、CRM、MES、Excel、邮件和个人经验里
- 结构不统一，同一件事在三个系统里三个说法
- 历史数据质量差，缺字段、对不上、靠人工补录
- 权限复杂，谁能看什么、谁能改什么是政治问题
- 知识长期没人维护，流程改了文档没改

RAG 的坑大家已经踩够了：文档是旧的、分块是乱的、检索回来的全是噪音。Agent 也一样——它不可能凭空知道你的企业长什么样，你喂给它什么，它就活在什么世界里。

## 坎五：Agent 必须连接真实系统

只聊天没有业务价值。企业 Agent 最终要调用 CRM、ERP、MES、工单、数据库——这就是工具调用真正开始难的地方：

- 权限：Agent 的凭证能摸到哪一层？
- 接口稳定性：上游改了字段，Agent 静默用错数据怎么办？
- 状态管理：多步调用中途失败，状态停在哪一步？
- 异常重试：重试是幂等的吗？重复下单、重复扣款怎么办？
- 审计日志：每一步都有迹可循吗？

MCP 这类协议大大降低了"连接"的成本，但它只是插座的形状统一了——电线另一头连的仍然是千疮百孔的旧系统。协议降低的是集成门槛，不是业务集成的复杂度。

## 坎六：人机协作比"全自动"更重要

企业通常不需要 AI 完全替代人，也不该这么设计。正确的问题是**人和 AI 怎么重新分工**：

- AI 擅长：信息整理、方案生成、推荐、初步判断
- 人擅长：风险判断、最终决策、异常处理

高风险的节点必须保留 Human-in-the-loop。一个好的 Agent 产品，本质上是在重新设计"人和 AI 的分工"，而不是设计一个"把人的活全包了的 AI"。全自动听着性感，但企业要的是可控。

## 坎七：Demo 有效果，不代表产品有价值

这是最致命的认知差。**Demo 看生成效果，产品看任务完成率，企业看 ROI**。三者的关注点完全不同。

真正应该盯的指标是：

- 任务完成率（不只是"答出来了"，是"办成了"）
- 人工接管率（AI 有多少比例需要人兜底）
- 平均处理时长（省了多少时间）
- 错误率（特别是静默错误——错了还没人发现）
- 用户采纳率（员工真的在用吗）
- 单任务成本（Token + 人力的真实账单）
- 实际节省的人力 / 时间

Demo 里"哇，它真聪明"的瞬间，很难翻译成其中一个指标。翻译不出来，就只是自嗨。

## 坎八：最后的问题往往出在人，而不是 AI

技术问题都好解决，组织问题最难。我见过的真实情况：

- 员工不愿改变原有工作方式——用了 AI 反而增加操作步骤（先录数据、再复核 AI 结果）
- 管理层期待过高——Demo 演示后觉得"明天就能上线"，落地期失望反噬
- 业务人员不信任 AI——尤其是出错一次之后，永远不再用
- 没有明确的负责人持续维护——上线三个月后知识过期、Prompt 失配，悄悄停用

Agent 落地本质是一场**组织流程变革**，不只是上一个系统。不给它配流程、负责人和信任，再好的 Agent 也会烂在角落里。

## 更合理的落地方式

绕开这 8 道坎，不是靠更强的模型，而是靠更稳的路径：

1. **先找高频、重复、价值明确的任务**——价值可量化，场景才立得住
2. **判断是否真的需要 Agent**——Workflow / 规则 / RAG 能解决的，别上 Agent
3. **从小场景 MVP 开始**——一个场景跑通，再谈扩展
4. **保留人工审核和异常兜底**——把"错了怎么办"设计进第一版
5. **用真实业务指标验证价值**——按坎七的指标，跑一段时间看数据，不看感觉
6. **跑通之后再逐步扩大自动化范围**——信任是赚来的，不是拍来的

## 一句话总结

企业级 Agent 最大的挑战从来不是模型能力，而是**业务、数据、系统、风险和人的共同约束**。Agent 不该被定义成"更聪明的聊天机器人"，而是一个**能够进入真实工作流、在可控风险下稳定完成任务、并持续创造可量化业务价值的 AI 系统**——做到这三件事，它才配叫落地。
